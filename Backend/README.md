# Inside The Book backend API formats

All API request and response bodies use JSON unless an endpoint is described as
`multipart/form-data`. The API is served by FastAPI; `/docs` provides its
interactive OpenAPI documentation. API paths are defined in the repository's
`shared/api-config.json`.

## Health

`GET /api/health`

```json
{
  "status": "healthy"
}
```

## Authentication

`POST /api/auth/login` accepts JSON:

```json
{
  "username": "admin",
  "password": "your-password"
}
```

The response is JSON with this shape:

```json
{
  "id": 1,
  "role": "admin",
  "name": "Admin",
  "username": "admin",
  "username_status": true,
  "pwd_status": true
}
```

For an unknown username, the response fields have their default values
(`id: 0`, empty strings, and `false` statuses). For a known username with an
incorrect password, `username` is included, `username_status` is `true`, and
`pwd_status` is `false`.

## Books

### Read books

- `GET /api/books` returns an array of books.
- `GET /api/books/{book_id}` returns one book or `404` when it does not exist.

A book response has this shape:

```json
{
  "id": 12,
  "title": "Example title",
  "author": "Example author",
  "editor": "",
  "distributor": "",
  "description": "A short description.",
  "year": "2025",
  "new": true,
  "vols": [
    {
      "id": 3,
      "title": "Volume 1",
      "number": 1,
      "images": [
        {
          "id": 8,
          "image_url": "https://example.com/volume-image.jpg"
        }
      ]
    }
  ],
  "images": [
    {
      "id": 7,
      "image_url": "https://example.com/book-cover.jpg"
    }
  ]
}
```

### Create a book

`POST /api/books` uses `multipart/form-data`, not a raw JSON request. Send exactly
one text field named `payload` whose value is a JSON string. Every image is a
separate file field named for its slot; reference that same slot in the JSON.
Each slot can be referenced once, and each uploaded file must be referenced.

Example `payload` value:

```json
{
  "title": "Example title",
  "author": "Example author",
  "editor": "",
  "distributor": "",
  "description": "A short description.",
  "year": "2025",
  "new": true,
  "images": [
    { "slot": "cover" }
  ],
  "vols": [
    {
      "title": "Volume 1",
      "number": 1,
      "images": [
        { "slot": "volume-1-page-1" }
      ]
    }
  ]
}
```

The matching form fields are:

| Form field | Type | Value |
| --- | --- | --- |
| `payload` | text | The JSON above, serialized as a string |
| `cover` | file | The book cover image |
| `volume-1-page-1` | file | The volume image |

The `images` and `vols` arrays can be empty or omitted. Book fields other than
`title` are optional when creating a book; `author`, `editor`, `distributor`,
`description`, and `year` default to empty strings, while `new` defaults to
`false`. Volume `title` and `number` are required. Image slots must contain
1–100 letters, numbers, underscores, or hyphens.

Allowed upload types are JPEG, PNG, and WebP, with a maximum size of 5 MiB per
file and 200 files per book. On success, the endpoint returns the created book
as JSON with status `201`. Image URLs and storage keys are generated by the
backend; clients should send slot references, not URLs or storage keys.

For example, with `payload.json` containing the JSON above:

```sh
curl -X POST http://localhost:8000/api/books \
  -F 'payload=<payload.json' \
  -F 'cover=@cover.jpg;type=image/jpeg' \
  -F 'volume-1-page-1=@page-1.webp;type=image/webp'
```

### Update and delete books

`PATCH /api/books/{book_id}` accepts a JSON object containing any subset of these
fields:

```json
{
  "title": "Updated title",
  "author": "Updated author",
  "editor": "",
  "distributor": "",
  "description": "Updated description.",
  "year": "2026",
  "new": false
}
```

Fields omitted from the request are left unchanged. A successful update returns
the updated book; a missing book returns `404`.

`DELETE /api/books/{book_id}` returns `204 No Content` when deleted, or `404` when
the book does not exist.

## Local configuration

Copy `.env.example` to `.env` and set the required values for your environment.
`ALLOWED_ORIGINS` is a JSON array of browser origins, for example
`["http://localhost:3000"]`. `DATABASE_URL` defaults to a local SQLite
database. Image uploads require `SUPABASE_URL`, `SUPABASE_KEY`, and
`SUPABASE_BUCKET`; keep the server-side key private and out of client code.
